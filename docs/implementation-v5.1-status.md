# Looma 5.1 试用准备实施记录

启动日期：2026-10-29；最终验收：2026-10-31，Asia/Shanghai。承接用户要求继续优化及上一轮六项试用前建议。范围与责任见 [实施清单](plans/2026-10-29-trial-readiness.md)。既有v3-v5改动保留，未提交、推送、发布或联系使用者。

## 本轮变化

- 新增独立“放心练习一次”，纯内存状态机复用实际解析、候选校验、编辑、收尾及撤销组件。演练没有Repository/IndexedDB/IPC/模型调用，关闭即丢弃，不安排真实提醒或导出纪要。
- 打开演练前等待真实草稿保存；写失败保持原输入。原WorkBench保持挂载，演练关闭后继续原文、项目选择和手改候选。弹窗期间底层工作区使用原生inert，关闭按钮自动聚焦，避免Tab进入真实确认按钮。
- 主操作改为“整理并核对”；合作归属使用更直接的说明。基础本地流程可直接开始，模型设置为可选且默认折叠；语义确认和不猜人物的边界保持。
- 新增“版本与问题记录”。显示产品版本和具体构建号，默认报告只包含构建元信息、时间、空间/步骤枚举、通用错误编号。使用者可主动填写预期、实际和是否可重复，预览并勾选脱敏后自行复制/下载；无自动网络、持久遥测或客户资料采集。
- 合成语言矩阵覆盖16种表达，新增“先别定／还没拍板”等未确定预算保护，金额不作为确定值，原表达保留为待确认问题。案例仅属工程验证。
- 增加无需目标进程Node/npm的Windows内部验证便携包及构建脚本。构建号绑定当前未提交源码及实际运行依赖字节；构建和打包共用同一运行清单，逐项SHA256核对。已有同名构建不覆盖。独立干净机器、签名与安全依赖升级未完成，包不宣称可安全公开分发。
- 提供 [15分钟观察任务卡](试用前任务卡.md)，区分演练临时状态和独立合成测试工作区里的草稿恢复观察。不使用日常客户工作区试错，不虚构用户观察结果。

## 实施决定

- 演练采用纯内存状态机，复用核心规则和回执界面，不增加持久存储“演练分区”。代价是演练关闭后不恢复，界面持续明确这一边界。
- 本轮保持已安装的Electron和原生模块，不将便携打包当成安全升级。完整性校验用于绑定和检查本地构建内容，不替代可信来源、数字签名或安全审计。
- 反馈只接受粗粒度上下文和用户主动填写，不提供默认完整日志/数据库导出。代价是负责人仍需根据脱敏描述复现问题，当前不建设遥测平台。
- v5商业材料、核心PRD和Word仍记录v5核心旅程；5.1内部试用准备作为本附录及README补充，不把尚未进行的真实用户观察写成产品成绩。
