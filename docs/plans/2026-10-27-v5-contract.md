# v5 并行接口冻结

类型以src/types.ts新增定义为准，root独占types与Repository/App；不得另造同名接口。

记录kind新增capture_draft（id固定active-work，含唯一sessionId）、followup、closure，仅work可用。CaptureDraft含sourceVersion（输入/归属改变时递增）、draftVersion（所有编辑递增）、proposal、conflicts。来源ID由sessionId/sourceVersion稳定构造，重试不造新来源；原文可在首次整理时归档，commitCapture也确保来源存在。

backend.request新增：
- {op:'saveDraft',space:'work',draft} => {ok,error?}；不改业务revision，不记撤销事件，拒绝同session较旧draftVersion。
- {op:'commitCapture',space:'work',draftSessionId,proposal,confirmedAt,originalOnly?:boolean} => {ok,closureId?,eventId?,already?,error?}。按proposal.id幂等且内容匹配；业务+事件+closure+删除active-work草稿原子。originalOnly允许空operations，准确回执不宣称业务更新；sourceMessageId对应原文必须存在/一致。closure id为closure-${proposal.id}，eventId为event-${proposal.id}。同一批次返回同一回执。重复已提交命令不要求草稿仍存在。
- {op:'workHome',space:'work',now,limit:3} => {draft,today,overdue,waiting,questions,recent,counts:{today,overdue,waiting,questions}}；各数组最多3，按Asia/Shanghai分今日/逾期，waiting/question不混作我方逾期。提醒/状态索引，不能全库读到前端。
- undo允许eventId可选，指定时仅撤销确实最近的该event；撤销对应closure写revertedAt，不恢复草稿。
- transaction的capture_draft/closure等派生写不递增业务revision；followup为业务变更。来源redactSourceIds需清关联草稿；closure只保存引用，不另复制原文。

bootstrap返回schemaVersion5，work追加followUps/closures有界数组，life不扩展；v3/v4恢复向前兼容。JSONL头version5，接受version4；Web export version=looma-v5，接受looma-v4与v3完整JSON。原生与IDB行为相同。

Repository由root提供：getCaptureDraft(),saveCaptureDraft(draft),commitCapture(draft,originalOnly?),getWorkHome(now?),setItemState(kind:'task'|'followup',item,done):Promise<CaptureCommitResult>,undo(space,eventId?)。CaptureCommitResult区分committed/rejected/unknown，已成功写入而refresh失败仍committed且refreshWarning，真实未知保留草稿并按稳定closureId核查。

解析器context扩展newClientName/newProjectTitle，明确绑定普通姓名、不猜姓名；propose返回clarification可选。followup放入operations target='followup'。capture.ts纯函数：createCaptureDraft(now?),reviseCaptureDraft(draft,patch),rebaseProposal(proposal,partition):{proposal,conflicts},resolveProposalConflict(proposal,conflicts,id,choice):{proposal,conflicts}。冲突id以target/entityId/field稳定定位，conflict字段见types。

UI WorkBench props在现有props基础追加draft,draftSaveState,home,closure,onDraftChange(patch),onContinue,onResume,onOriginalOnly,onRebase,onResolveConflict,onSetItemState,onUndoEvent,onOpenMemory。完整定义root将同步；UI不自行写仓储业务，列表查询沿用Repository.query。ProposalReview额外conflicts/onResolveConflict，四类展示，保留旧aria labels以便回归。ClosureReceipt({closure,source,events,engagements,tasks,followUps,onProject,onContinue,onExport,onUndo})。
