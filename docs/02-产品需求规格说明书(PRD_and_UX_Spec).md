# Looma（灵犀胶囊）产品需求规格说明书

版本：v5.0 · 批准日期 2026-10-27。目标版本：沟通有清楚收尾、下次处理有可靠起点的本地单人试用改善版。实际完成状态以implementation-v5-status.md和验收输出为准。

## 一、目标用户与首轮范围

首发用户为独立接单者、顾问和小工作室主理人。核心任务是刚聊完能记清，被打断能继续，隔几天能接上，发现错误能改对。“网站开发者同时处理多个客户”为假设案例，用于设计与工程验收，须由后续真实目标用户核对，不能表述为已有访谈结论。

工作态承担本轮商业验证。生活态继续保留记账、个人状态、亲友备忘与手账，首轮只处理必要的隔离、迁移和恢复兼容问题。自报身体状态仅为个人记录，不表现为客观测量或诊断。

本轮不做语音转写、截图识别、任意结构造卡、官方云模型、云同步、账户支付、多人 CRM、团队权限或退出应用后的后台提醒。

## 二、首页、草稿与沟通收尾

1. 空工作区突出“记下刚才的沟通”，演练入口明确标注，不生成真实客户。有资料后提供未完成整理、今日事项与最近沟通，每组先显示最多3项，可进入完整列表；今日和逾期分开，等待客户与未定问题独立呈现。
2. 输入、项目归属和手动编辑候选在停止编辑500毫秒后尝试本地保存，显示未保存、保存中、已保存或失败。草稿不改变业务版本；查看记忆、项目、切换空间后可继续。正常桌面退出前尝试保存；浏览器离开前提示未落盘内容，异常关闭只承诺最近成功保存的版本。
3. 本地规则或主动开启的模型提出候选，项目尚不改变。人物或项目不明确时只追问关键归属，可搜索已有项目，或明确填写普通姓名并预览新建；用户不必重写原文。也可仅保存原文，准确说明未更新项目或安排提醒。
4. 核对页按项目呈现核对内容、我方下一步、等待客户和仍待确认；优先展示变化、修改前值和原文依据，完整字段按需展开。用户可编辑、忽略或返回继续整理。
5. 确认后校验结构、关联和基础版本，在同一事务内保存业务、变更事件、持久收尾记录并结束草稿。回执说明保存了什么、我方行动、等待及未定内容，提供查看项目、继续记录和准备纪要；存在等待或未定事项时不称“全部完成”。

未确认时使用“待核对”“发现候选变更”，不得说“已更新”。回执中的“已核对”只表示用户核对了记录，不代表客户已经确认共识。无法理解的内容保留原文供核对，不编造预算、行动、人物或成交结果。失败写入、连接失败或无可识别内容，不得以陪伴模板伪装为记录成功。

同一输入版本和批次重复确认返回同一回执，不重复行动。提交结果分为已提交、被拒绝和暂不确定；成功写入但刷新失败时说明已保存、可重读，结果暂不确定时保留草稿并按批次核查。旧预览遇到新编辑时保留输入与手改；基础值未变的编辑可沿用，冲突字段展示当前值和拟修改值，由用户选择。

项目详情集中当前值、下一步、等待项、问题与最近依据，可从预算或行动进入修改。自然语言和推断先核对；明确完成或重新打开直接保存，成功才更新状态，失败留在原列表并保留原状态。撤销绑定对应最近事件，不能撤销后续操作，也不重新激活已结束草稿。

生活态保留原有识别交互，但一条输入涉及的生活业务更新必须一次保存，并按来源消息防止重复应用；原文与回复分别保存。业务成功而回复保存失败时，界面明确提示记录已经保存、请查看卡片且不要重复提交，不能将回复故障解释成业务未记录。

## 三、客户合作项目与待办

客户合作项目包括客户名称、项目标题、可未知的预算、当前阶段、内部资料、可外发摘要和下一步行动。同一客户可有多个合作项目；名字相同或指代不清时要求选择目标，不默认修改第一位客户。

待办包括标题、完成状态、优先级、可选项目关联、原始截止日期表达与确认后的时间。旧资料中无明确关联的任务保留为未关联，不自动猜测归属。

等待客户和待确认问题使用独立跟进项，包含项目、标题、开放或已处理状态与来源。客户预计提供日期／时刻与用户自设回访时间分开保存；未设置回访时间不自动催促。费用尚未谈定形成问题，不填入确定预算。

必须覆盖以下语义边界：

| 输入示例 | 预期行为 |
| --- | --- |
| “王总预算 300 元” | 候选预算为 300 元，不能按小数额自动乘一万 |
| “预算从 8 万改为 12 万” | 在目标项目明确时提出最终预算 120000 元 |
| “还没成交” / “如果成交” | 不提出已经赢单的状态 |
| “张总和李总预算不同” | 分清实体，信息不足则提示核对，不互相覆盖 |
| “预算 300” | 提示单位待核对，不猜测元或万元 |
| “下周三前发方案” | 以输入时的 Asia/Shanghai 日期解释，并展示绝对日期 |
| “我周五发原型，客户下周一补素材，新增页面费用未定” | 我方行动、等待客户与未定费用分别记录，不把客户事项算成我方逾期 |

我方待办只有日期时默认当天09:00提醒，确认时可修改；客户只说“下周一”时保留日期粒度，不能把09:00补成对方承诺。歧义或不支持的时间表达保留原文，不能静默变为臆测日期。

## 四、空间与隐私交互

生活和工作采用同一本地应用中的逻辑分区。每次读取、写入、查询、日记生成、回执和导出都指定当前空间；关闭跨区关键词写入与工作压力扣减生活精力。

切换空间后，旧请求结果仍只属于发起请求的空间，不覆盖当前界面。工作态不展示生活记录、记忆或手账。

用户在当前空间主动输入的原文仍保留在当前空间；“未跨区写入”不能被描述为已经从原文中清除了全部隐私。界面使用“本地逻辑分区”等真实表述，不显示“物理隔离”“私人数据已加密”或绝对防窥承诺。

首次真实工作区为空；示例内容通过明确入口展示，不计入真实客户或预算。旧数据迁移不调用自动返回示例内容的默认 getter。

## 五、模型增强与失败反馈

默认基础流程在本地运行，覆盖有限中文规则。Windows 桌面可以主动开启自配 OpenAI 兼容模型或 Ollama；浏览器预览仅支持本地流程，不索取模型 Key。

开启模型增强时说明发送范围：当前输入和所选项目必要字段，默认不附加内部备注、其他项目或另一空间资料。模型只提出候选，不调用写入工具，不直接修改记录。

模型配置状态应区分未配置、关闭、已配置、请求中、成功和失败。主进程保存并使用 Key，界面保存后只显示是否已配置。超时、取消、无效结构或服务失败均保留原文供重试，重试不得重复提交业务变更。

检测到旧凭据时，每次桌面启动继续尝试安全迁移；不覆盖已配置的新连接或 Ollama，旧连接加密归档。只有加密落盘成功后才清理旧浏览器字段，迁移或清理失败时下次重试。用户清除模型配置时同时清除当前连接与旧连接归档。

## 六、提醒与重新打开

工作台提供今日与逾期我方待办；等待与未定项不混入。应用运行（含胶囊状态）时检查到期事项，可发出不含客户名称、报价或内部备注的系统提示；系统通知不可用时保留应用内提醒。预计客户日期仅作记录，用户明确设置回访时间才用于回访提醒。

重新打开时汇总遗漏事项，不逐条制造通知风暴。已完成任务不提醒；相同任务的同一到期提醒避免重复。退出应用后不继续后台提醒，不启用开机启动或托盘常驻机制。

## 七、沟通纪要草稿

默认标题为“沟通纪要草稿／待对方确认”。内部沟通收尾卡的“准备纪要”进入独立审核流程；用户选择项目与需要带出的事项，编辑并预览后可复制文本或导出 PNG。收尾卡不直接作为外发文件。

外发草稿只由明确允许的字段构造，不读取原始聊天、内部资料、未确认内容或另一空间。预算默认不选入。任务是否带出由用户勾选；缺少对方确认依据的内容不能自动标成“已达成共识”或“我方承诺”。

内部字段排除不能保证用户主动填写的可外发文字中一定没有敏感内容，因此最终预览必须显示实际将外发的全部文字。产品不自动发送纪要，也不替客户确认内容。

## 八、备份、恢复与验收

应用与完整备份升级v5，包含两区业务、自定义卡、日记、事实、摘要、变更历史及新增草稿、跟进项和收尾记录，不含凭据。接受v3/v4完整资料，缺少新类型按空集合处理，旧业务值保持原样。库版本与索引升级在可回退事务内完成；恢复先完整校验再原子替换。无旧5MB硬限制，浏览器仍受内存和配额约束，桌面大备份使用流式JSONL和暂存库。

若本地快照损坏导致工作区无法打开，错误边界保留原始数据，提供“选择有效备份 → 明确确认替换双空间 → 校验并恢复”的入口。坏备份或恢复写入失败不覆盖原快照，不自动清空数据来掩盖读取错误。

工程验收覆盖完整旅程、草稿中断/刷新/重启、仅存原文、普通姓名、多人物、预算300元、金额更正、否定假设、责任分类、日期粒度、双击确认、结果未知、成功后刷新失败、明确操作失败、旧预览冲突及迟到模型。另验旧库升级、坏备份不覆盖、完整恢复、撤销、删除传播与万条历史下有界查询。浏览器与Electron必须实际运行，静态检查不能替代；现有Electron依赖链高危审计项仍为公开分发门槛。

商业试用另由负责人安排5名目标用户完成7天实验，先核对假设案例，再记录耗时、修正、重复使用、纪要采用、付费意愿，以及责任辨认、中断恢复、跨日接续与仍需原工具补做步骤。目标阈值与成绩分开，未执行不宣称收益已验证。

## 九、原创伴侣与胶囊

伴侣采用原创小精灵：暖白浅绿、圆润豆形、双叶冠、深绿眼睛与短四肢。生活态和工作态是同一个Looma，不使用真人或IP替身。SVG与CSS在本地显示，不依赖图片网络请求。工作时克制、生活时轻微浮动；遵从减少动态效果设置，按钮支持键盘。

状态由真实信号决定，优先级为错误、处理中、待核对、刚保存、到期提醒、空闲。保存失败不得显示成功动作；提醒依据真实未完成事项，不制造“想你了”等虚假事件。

保持用户自主与容易纠错：主要变化直接可见，完整表单和高级操作按需展开，不让说明、统计与完整表单同时占满首屏。不增加亲密承诺、未使用惩罚或虚假关怀通知。

桌面将同一窗口收起为220×96胶囊，展开恢复先前尺寸与位置；浏览器只收起页内界面。胶囊不显示客户名、金额、原文或内部资料，仅显示角色、空间、通用状态与事项数量。不增加第二个桌宠窗口，不抢焦点、不播放声音。

## 十、长期记忆与增长治理

记忆分为近期会话、明确确认的长期事实、当前业务实体、可重建阶段摘要与本地原始档案。原始历史默认本地保留，由用户主动删除；新工作区为空。底层UI缓存每类最多50条，工作首页每组最多3条，记忆档案每页30条，可搜索与加载更早记录。生活账单卡明确只汇总已加载记录，不能把近期小计标成完整月度支出。

事实必须主动核对。相同事实不重复添加，同一主体和主题的不同内容先展示冲突，确认后保留旧版为被替代记录。支持查看来源、纠正、置顶和忘记；忘记停止默认回忆并清理关联摘要，原文默认仍可手动查阅。

用户另选删除原文时，在同一事务中删除原文、关联草稿、搜索索引与事件原文副本，停止依赖事实的自动回忆；清理当前原文缓存和派生展示，撤销不恢复这些原文。独立确认的业务字段仍保留；旧版回退快照及导出备份是独立副本，由用户另行处理。当前能力是逻辑删除，未提供磁盘取证级擦除。

“只读回忆”入口与记录入口独立，不能更新预算或任务。当前项目值优先于事实和历史，摘要不转换为新事实。每次回忆默认最多12条、约4800字符（按字符估算）；资料中的指令仅作为引用。记忆模型增强另行授权且默认关闭，先查找和审阅依据，再主动发送已展示的有限证据；不自动上传全库、内部项目备注或另一空间资料。
