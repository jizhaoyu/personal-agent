# Looma v5 实施与验证记录

日期：2026-10-27，Asia/Shanghai。范围是用户已批准的沟通收尾与项目接续改善版。沿用当前分支和已存在的 v3/v4 未提交工作；没有提交、推送、发布、联系试用者或自动发送客户资料。网站开发者多客户情境只作为合成设计及验收案例。

## 已实现

- `CaptureDraft`、`FollowUpItem`、`ClosureRecord`，双后端共享校验。工作草稿停止输入 500ms 后保存，编辑版本独立于业务版本；支持输入、项目归属、候选与手动修改恢复。保存失败保留原文并明确提供重试。
- 打开记忆、设置、切换空间前保存草稿；浏览器对尚未保存的输入给出离开提示。桌面正常关闭先等待渲染进程保存，失败或超时默认返回应用，由用户明确选择才放弃退出；关闭请求编号拒绝迟到回执。异常关闭只恢复最后一次成功保存的数据。
- 普通姓名通过明确新客户输入或已有项目选择绑定；多人、多项目不自动选第一个。单一明确客户在同次输入的后续句子继续保持归属。金额单位、否定、假设和日期保护沿用并补测。
- 四类核对内容：本次项目变化、我方下一步、等待客户、仍待确认。保留前后值与来源；客户日期和具体时刻分开，我方回访时间独立且默认不设置。只有显式设置的回访时间进入到期通知查询。
- `commitCapture` 同事务提交业务、事件、收尾记录、结束草稿；稳定批次与持久幂等标记。重复确认、丢失回执重试、重开回执不会重复行动。旧预览可以三方重核，保留手改并要求明确选择冲突；迟到重核或模型结果不能覆盖新编辑。
- 明确完成、重新打开和标记已收到直接保存，成功后更新界面，留在原列表；撤销绑定事件并拒绝误撤销后续操作。收尾撤销标记历史状态，不自动重新打开已经结束的草稿。
- 首页提供草稿接续、今日、早前安排、等待、未定与最近沟通。各组先返回最多 3 项，使用后端索引；完整项目、行动、跟进和历史继续分页。项目详情集中当前值、行动、等待与最近依据；记忆中心引导到项目纠正业务值。
- 历史回执从本次事件还原字段，不把后来修改的项目预算补入过去记录；依据缺失时明确说明不可还原。纪要入口使用当前项目，继续独立审核，内部备注和待确认问题不自动进入外发材料，预算默认不选入。
- 应用及备份格式升级 v5，接受 v3 快照和 v4 完整备份。保持原 SQLite 和 IndexedDB 名称，不另建空库替代旧资料；补齐状态/时间索引。恢复前完整校验、原子替换，包含草稿、跟进、回执、自定义卡、两区资料、事件和幂等标记，不含凭据。
- 恢复成功后失效旧候选缓存及异步回执；恢复确认成功而界面读取失败时，明确表示已恢复并允许重读。已恢复资料不会被恢复前草稿再次覆盖。
- 原创小精灵及生活功能保留，生活为可见次级入口；工作首屏缩小角色并合并重复入口。胶囊与系统通知只展示通用状态和数量，继续采用本地逻辑分区表述。

## 审查后补充修复

1. 同一客户跨句后的行动与等待曾丢失归属，已补精确输入回归并修复。
2. 模型省略实体 ID 不能绕过明确项目限制或伪造新客户，不能把客户动作改为我方行动。
3. 严格拒绝 2 月 31 日等会被 `Date.parse` 自动归一的时间值；客户日期保留日期粒度。
4. 明确区分写入拒绝、结果不确定、已保存但读取失败；草稿、业务提交及完整恢复均有相应路径。
5. 恢复备份后清理旧批次成功缓存并隔离迟到响应，避免旧缓存假报新数据库已提交。
6. 迟到重核绑定草稿会话、版本与操作序号；进入记忆或安装新草稿会取消旧模型请求。
7. 历史回执不以当前业务字段冒充过去核对值；事件依据缺失时明确显示不可还原。
8. 普通提示不会附带其他操作的撤销按钮；新草稿编辑会结束上一笔已保存状态提示。

## 限制与后续验证

- 这是本地真实案例试用改善版，尚未完成公开分发安全验收。既有 Electron/extract-zip 依赖链高危审计项仍须在公开分发前升级、重建原生 ABI 并复测；本轮没有静默大版本升级。
- 所有模型检查使用受控响应或本机受控服务，未验证真实云服务或真实 Ollama 模型连通/准确率。原生通知 API 返回 `shown:true` 只证明 API 接受显示，不证明操作系统一定向用户展示或用户已经看到横幅。
- 应用退出后不提醒；胶囊属于应用仍在运行。异常退出只保证最近一次成功保存的草稿。数据库是本地逻辑分区，业务文件本身未加密。
- Word 检查基于当前 WPS/字体环境，其他 Office 分页及真实打印未验证。
- 没有安排或联系真实目标使用者。5 人、7 天、约 50% 耗时改善及重复使用阈值继续作为实验目标，不能当作既有成绩。
- 旧版 v4 完整浏览器脚本保留为历史场景；本轮运行的是本记录列出的 v5 及兼容检查，没有把未重新执行的旧脚本计为本轮通过。
