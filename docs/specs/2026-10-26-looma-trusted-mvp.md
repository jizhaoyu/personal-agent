# Looma 可信单人客户跟进 MVP 设计规范

批准日期：2026-10-26。依据：用户在方案审查中确认首发人群、试用阶段、预览确认写入、文字输入、自配模型、双态严格分区、桌面完整与 Web 本地、运行时提醒，并明确要求实施完整计划。

## 目标和成功标准

服务独立接单者、顾问和小工作室主理人。文字或手动粘贴沟通记录，经候选预览、修改与确认，更新持续维护的客户合作项目和待办，再准备可审核的沟通纪要。

工程成功标准为正确处理关键金额、否定语义和日期，确认前不写业务实体，整批提交可撤销，空间不串台，备份可完整恢复，生产桌面无需 Vite，外发不含内部字段。运行与自动化结果另记，不以本规范表示已通过。

## ADR 01：单人真实案例试用优先

使用者、购买者与数据拥有者尽量保持一致。保留生活态，不扩展生活功能；工作态承担本轮商业验证。不建设账户支付、多人 CRM、团队权限、官方云服务或同步。

代价：本轮无法验证企业采购或团队协作价值。收益：可以把整理耗时、重复使用和付费意愿与明确任务相联系。

## ADR 02：候选与提交分离

`StateEngine.propose` 只生成 `ProposedChangeSet`，包含来源、空间、基础版本、操作和警告。用户可修改、忽略单项或取消整批。`validate` 检查结构和目标；`commit` 是工作态唯一业务写入口，产生 `CommittedChangeEvent` 与成功回执。`undo` 倒序撤销最近变更。

同一候选重复确认幂等，过期预览不得覆盖后续编辑，一次输入全成或全败。工作记忆提取不得另行后台写库。未知金额、人物和歧义日期保留待核对，不编造确定状态。

## ADR 03：本地版本化快照与逻辑分区

使用 `looma_app_v3` 存储 `AppSnapshotV3`，含 `life`、`work` 分区与无凭据普通设置。每次仓储访问指定空间；正常修改只作用于一个分区。停止关键词跨区路由与工作精力桥。

完整快照先在内存校验，再单次写入。旧实际键迁移不通过会生成示例的 getter；非凭据旧键保留回退。无 mode 旧日记默认生活态；无关联旧任务保持未关联；旧 CRM 自由文本迁入内部资料。备份完整校验后原子替换，失败保持原数据。

代价：浏览器存储有体积与配额限制；本方案不提供业务数据加密、多用户权限或物理隔离。写入失败必须显式报告，界面不得先显示成功。

## ADR 04：桌面受控自配模型

Windows Electron 主进程用当前版本可用的 `safeStorage` 保存 Key 并代发请求；不可安全保存时仅会话使用，不明文落盘。界面保存后只读取状态。业务备份、日志和事件不含 Key。旧明文 Key 在成功安全迁移后移除。

用户主动启用 OpenAI 兼容模型或 Ollama 后，发送当前输入及所选项目必要字段，默认排除内部备注、其他项目及另一空间。模型只返回结构化候选，经过验证后进入预览，不执行工具或写库。设置超时与取消，失败保留原文供重试。

Web 预览仅提供本地流程，不管理远程 Key。保留 contextIsolation、关闭 Node 集成、启用 webSecurity，限制导航与 IPC 来源。

## ADR 05：纪要是可审核草稿

`AlignmentDraft` 独立于内部记录，默认标题“沟通纪要草稿／待对方确认”。只使用用户选定且允许外发的字段和待办；内部备注不属于草稿类型，预算默认未选。预览可编辑，用户核对完整内容后复制文本或导出 PNG。

没有对方确认依据时，不使用“已达成共识”“我方承诺”等确定性表述。排除内部字段不能保证自由文本没有隐私，最终预览不可跳过。产品不发送材料，不代替客户确认。

## ADR 06：日期和提醒边界

日期按输入时的 Asia/Shanghai 解释，并显示绝对日期；只有日期没有时刻时默认 09:00，可在确认时修改。歧义表达保留原文待核对。

应用运行时检查到期事项；重开汇总遗漏。系统通知不展示客户细节，通知不可用则保留应用内提示。已完成任务不提醒，同一到期事项避免重复。退出后不继续运行，不设置开机启动或托盘驻留。

## 证据与验证

自动化覆盖解析、校验、批次提交、幂等、撤销、迁移、导入、失败写入、日期、隔离和模型异常；浏览器验证完整交互、刷新恢复和导出；Electron 验证构建启动、凭据、连接与通知；Word 汇编须渲染逐页检查。

商业实验为 5 名用户、7 天，由项目负责人组织。约 50% 的整理耗时下降与至少 3 人跨 3 天使用是待验证目标，不能写成已有成绩。
