# Looma 随心记下：Personal Agent 交互设计

状态：用户已确认“随心记下”原则；无时间事项先保存已实施。本文描述后续跨模块设计，不能作为已开发或已验收的声明。

## 产品目标
用户不先整理，不必学习客户、项目、待办或记忆的分类规则。随口输入后先可靠保存原文，再理解、归属和接续。伙伴感来自可靠、连续和克制，不来自消息数量。

## 两层交互
1. 快速记录：统一文本入口，不必填写标题、时间、优先级、客户或项目；生活与工作使用同一交互习惯。
2. 深入整理：现有项目、依据、核对及变更历史作为按需展开的工具，不在每次记录时必经。

模式是查看和隐私边界，不应成为记录的前置表单。当前空间明确则留在当前空间；不能把生活资料默认发送到工作模型上下文。跨空间归属不明确时先保留，不擅自改空间。

## 必须区分的状态
- 原文已保存：即使模型失败也成立，用户无需重说。
- 事项已理解：原文关联到行动、等待、问题、事实、想法或普通交流；一段可以包含多个类型。
- 提醒已安排：只有存在明确可执行时间、启用状态和权限能力时才能这样反馈。
- 重要事实已核对：涉及预算、客户承诺、项目阶段等，不得把自动提取等同用户或客户确认。

不要求用户补完信息才能记住。无日期任务允许保留、完成、取消；提醒时间是可选增强。普通计划仍先建议，不静默转为正式承诺。

## AI 的职责与执行边界
模型用于复杂口语、同句多事项、跨轮指代、纠正、撤销和来源关联；简单完整指令走已有低延迟本地路径。模型输出为带来源、实体ID和当前版本的结构化候选，不能直接写SQL或凭空指定实体。

本地执行器负责校验白名单、当前版本、模式隔离、幂等、时间、来源及冲突。重要业务变更沿用原核对流程，但只展示变更差异；不能为减少点击而把未知预算或客户承诺变成事实。

多事项必须逐项检查：混合“买牛奶”和“陈总预算三万”不能整段吞成一个待办，也不能漏掉其中一项。无法理解先保留原文，提供非阻塞的稍后整理入口。

## 口语连续对话验收样本
| 输入 | 必须观察的结果 |
|---|---|
| 找时间把电费交了，先记着 | 保存无日期事项，不开启闹钟，不强迫补时 |
| 明天下午三点提醒我交电费 | 一条明确提醒，显示实际安排 |
| 下午三点提醒我交电费 | 先保存；日期仍未知，不补今天 |
| 老陈那个报价先别动，他还在等老板拍板 | 等待与暂停意图，不标完成、不猜客户身份 |
| 不是不做了，是这周先放放 | 暂缓，不完成、不永久取消 |
| 刚才说周五不对，周四中午前给他 | 修正唯一当前事项，保留旧值历史；中午前不等于擅定12点提醒 |
| 买牛奶，周五给小李合同，哦牛奶家里还有 | 保留合同；本次牛奶候选撤去；小李有歧义不选错人 |
| 她已经回我了，之前那个不用催 | 只有指代可验证时处理对应等待；不批量关闭其他客户 |
| 那个搞定了 | 有唯一上下文才完成，否则极短选择 |
| 电费不用交了 | 不标已完成；是否取消按对象和语义判定 |
| 电费是不是已经交了 | 查询，不完成 |
| 我以为已经发了，实际还没 | 保持未完成 |
| 今天累死了，啥也不想干 | 不创建任务，不机械催办 |
| 记一下这是客户说的，不是我答应的 | 保留说话者和来源边界，不生成为我方承诺 |
| 这两件都好了，第三件留着 | 核对会话顺序和真实实体，不按数据库任意顺序操作 |
| 不改时间了，还是原来那个 | 不凭空改期，不创建新事项 |

## 最终验收方案
- 至少200条独立口语样本和40条多轮会话；按意图和风险分层，避免只测标准句。
- 人工定义预期实体、状态、时间、来源和允许的追问；模型不能同时充当唯一被测对象和唯一裁判。
- 固定数据、时钟和隔离测试账户；每条检查数据库最终状态，不只检查回复文本。
- 模型实测使用用户指定的gpt-6.1-sol；记录模型名、HTTP状态、延迟、调用与重试次数。凭据仅进程环境注入，不进日志、备份和包。
- 成对运行本地路径与模型增强路径；比较误创建、误完成、错误关联、遗漏、重复、操作和追问次数。结果不预设模型一定更优。
- 全部测试覆盖生活与工作、同名客户多项目、多空间相似任务、跨日、改期、撤销、备份恢复和迟到响应。
- 使用最终打包EXE，隔离profile自动操作真实窗口，验证启动、输入法、连续记录、关闭留托盘、原文保留、到期、完成撤通知和重开不重发。
- 异常注入覆盖网络超时、模型非JSON、无效实体、存储失败、权限拒绝；不把失败显示为成功。
- Android真实设备不可用时明示未测；编译/JVM测试不能替代真机调度证据。
- 自动化证明工程行为，实际填写心理负担和长期价值仍以5人7天试用记录判断。
