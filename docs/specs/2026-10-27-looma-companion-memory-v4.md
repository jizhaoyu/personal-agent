# Looma 第二轮设计：可感知的伴侣与可持续的长期记忆

状态：用户已于2026-10-27确认设计与实施顺序，并选择方案A，允许新增兼容SQLite原生依赖。

本轮基于用户关于伴侣形象、产品特色和长期记忆增长的讨论。已确认：采用原创小精灵；原始历史本地归档，由用户主动删除；桌面SQLite与浏览器IndexedDB；按文末清单开始实施。

## 目标与验收方向

- 让同一个 Looma 角色贯穿工作与生活，用户能看见真实的待机、整理、待核对、保存、提醒和错误状态。
- 把近期上下文、已确认事实、业务当前态、阶段摘要和原始档案分开管理；历史持续增长时，日常页面与模型上下文仍保持有界。
- 原始历史不再因超过200条消息或500项事件而被自动截断；日常界面只加载分页数据。
- 保留上一轮确认、修正、撤销、工作/生活隔离、受控模型和安全外发的行为。
- 不将摘要或模型推测升级成已确认事实；每次回忆能够看到来源和时间。

## 已确认与推荐方案

### 伴侣呈现

原创暖白/浅绿小精灵，以轻量SVG/CSS实现：圆润豆形身体、叶形头饰、墨绿眼睛和短肢体。保留Looma名称，复用现有配色与动画能力，不引入Live2D、3D或外部图片服务。

推荐“内嵌伙伴 + 同一桌面窗口可折叠胶囊”。工作台将现有圆形L标记替换为角色，生活聊天复用同一角色。桌面收起后保留约220×96的角色入口，点击恢复展开前窗口边界；恢复时校正多显示器工作区。Web只在页面内折叠，不调整浏览器窗口。

备选：仅内嵌角色改动更小但常驻感弱；独立桌面角色需要额外多窗口、焦点与点击穿透管理，本轮不选。

状态优先级为 error > thinking > review > saved > reminder > idle。thinking仅对应真实异步工作，saved仅在持久化成功后短暂出现；提醒只展示数量，不展示客户或生活内容。工作态动作与语气克制，生活态更柔和，默认无声音、不抢焦点、不持续弹泡。支持键盘、状态文字和prefers-reduced-motion。

### 存储技术路线（已选A）

| 方案 | 价值 | 代价 |
| --- | --- | --- |
| A：桌面SQLite + Web IndexedDB（推荐） | 桌面事务、索引、分页、文件级可观测性；Web保留预览 | 新增原生SQLite依赖及Electron ABI验证；仓储改异步 |
| B：桌面与Web均IndexedDB | 不新增原生依赖，统一浏览器存储接口 | 仍受浏览器存储管理影响；全文索引、文件备份需自行适配 |
| C：保留JSON快照，加归档文件 | 局部改动较少 | 活跃业务增长后仍全量读写，不能作为本轮长期方案 |

推荐A：不夹带升级Electron。锁定运行时为Electron34.5.8/Node20.19.1，不使用Node22才提供的node:sqlite。实际npm核查采用兼容Node20的better-sqlite3@12.11.1（预研12.11.2未在registry发布）；开始替换前先验证Windows x64的Electron ABI加载、事务、FTS和重启。验证失败保留v3，不能静默切换另一方案或要求用户安装未说明的工具链。

SQLite只在主进程使用，位于当前应用userData下；复用可信IPC来源校验。原生构建和安装脚本必须可重复，应用名称不改，避免旧userData路径改变。浏览器预览通过同一异步仓储契约使用IndexedDB。

## 长期记忆设计

### 数据与来源

- 近期上下文：仅为界面与当前交互提供有界工作集，不是全部历史的唯一存储。
- 已确认事实：带空间、主体、主题、确认状态、来源ID、有效时间和替代关系。完全重复可合并；不同值作为待核对冲突，禁止只因时间较新便覆盖事实。
- 业务当前态：客户项目、金额、任务和账本仍是权威结构化数据，回忆当前预算时读取当前字段，不从相似旧聊天猜测。
- 阶段摘要：基于明确来源范围生成，可重建，用于定位历史。首版本地整理已确认事件，不在后台自动调用云模型；摘要不反向生成已确认事实。
- 原始档案：保存原文与历史事件，按空间和时间建立索引。归档继续保留，本轮不按期限永久删除。已有v3截断丢失的历史无法凭空恢复。

显式“记住”或用户确认过的事实才能进入长期事实层。通用聊天、临时情绪、假设和模型推断不直接进入长期事实。重要置顶事实不按访问频率淘汰；普通经历可以降低默认召回优先级，但原始档案仍可查询。

### 检索与使用

增加统一“记忆与档案”入口，工作/生活分别查询。提供近期、长期事实、历史档案、容量概况；支持分页、来源展开、纠正、置顶、归档与主动删除。

输入区区分“记录”和“回忆”。回忆只读，不生成业务修改候选；找不到依据时明确说明未找到。同客户多项目时先确定项目，不默认取第一条。

检索依次使用空间限制、人物/项目精确索引、日期/类型过滤、关键词全文搜索；首期不上向量库。中文2字姓名及常见短词必须有专门索引或受限回退，不能只依赖FTS5 trigram；单字全局查询要求缩小范围，避免无限档案下全表扫描。索引是可重建派生数据。

本地回忆可直接展示结构化事实与证据。模型增强继续由用户明确启用，仅加入当前空间相关且有效的事实和证据；设置独立的记忆字符/条数硬预算，显示估算用量，不声称精确token计数。当前状态与确认事实优先于历史摘要，不随总库大小增加注入量。

### 可控删除

删除前显示作用范围：事实、关联摘要/索引及是否同时删除原始来源。忘记事实时，停止默认召回其派生内容；若保留原文，档案页明确仍可手动查阅。删除原文则同步移除索引并使关联摘要失效/重建。业务实体不是普通聊天记忆，删除其业务字段需要明确操作，不随清理摘要误删。

备份中的历史副本有独立保留边界，界面不声称删除当前记录等于抹除用户已导出的副本。

## 仓储、迁移与故障处理

- 新异步仓储包含初始化、分页查询、读取选定实体、追加原文、提交批次、撤销、事实确认、档案检索和统计。UI启动只取小型bootstrap，正常IPC不返回全库。
- 解析器仍是纯函数，只接收当前选择及输入中涉及的候选实体；查询所需上下文后再解析，不先加载全部客户和任务。
- 主进程/IndexedDB事务保证原文追加幂等、批次提交与事件记录一致。业务revision与归档/索引维护版本分开，后台整理不使用户候选无故失效。
- 首次迁移允许读取现有完整v3一次；校验后事务导入，记录源指纹与迁移标记。成功前不改当前读取路径、不删除旧数据；重复启动不重复导入。失败保留v3并提供恢复。
- 查询和显示分页，常用页面控制返回行数；历史事件可全部归档，日常撤销工作集保持有界。
- 完整备份覆盖当前业务、事实、原文、摘要和来源关系，不含Key。大档案采用流式交换格式或数据库备份，避免继续受现有5MB上传限制和全库前端序列化约束；恢复先写暂存库，完整校验后切换，失败保留当前库。
- 业务数据默认仍是本地未加密资料，SQLite文件本身不等于加密。凭据仍由现有safeStorage路径管理，不迁入业务数据库。

## 实施顺序与测试

1. 冻结现有68项行为用例；验证SQLite原生兼容及异步仓储契约，明确可回退路径。
2. 建立数据库/IndexedDB后端、幂等迁移、分页与完整备份；切换读取前验证实体/来源/数量一致。
3. 接入事实治理、只读回忆、历史索引与本地摘要，验证预算变化、否定、冲突、中文短词与跨区隔离。
4. 接入小精灵、真实状态与桌面折叠；保留工作台操作，验证焦点、尺寸恢复、隐私和减弱动画。
5. 用超过旧限制的模拟数据测试（至少1万条原文、超过500个事件）；验证分页/IPC有界、重启恢复、迁移中断、磁盘失败、索引重建、删除传播及上下文预算；记录实际耗时，不预填性能成绩。
6. 重跑浏览器/Electron真实交互与既有业务回归，更新README、PRD、架构及Word汇编并渲染复核。
