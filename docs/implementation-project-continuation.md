# Looma 项目接续与依据追溯

日期：2026-11-04，Asia/Shanghai。仅优化本地个人端，保留此前文件清理与根目录 Word 归档改动；不提交、推送或发布。

## 已确认的设计与实现

- 面向多客户专业人士，在原项目详情集中呈现当前保存值、未完成行动、等待客户、未定问题和近期收尾；完成及已处理项折叠，内部备注单独折叠。
- 查询由独立只读接续服务承担，按项目关联分页，每页最多25条；来源按需查询，每次最多10条收尾记录，不自动遍历全库。
- 每个来源入口绑定具体实体与字段，只展示确实改变该字段的事件及其关联原文；已撤销、原文缺失、仅存原文和缺少关联分别处理。原文读取只使用消息记录，不以事件 sourceText 作为回退。
- 相同历史值仅称“历史记录中的相同值”，不宣称是当前值唯一来源；现有数据没有完整字段最后写入指针，不能补造该结论。
- 继续记录复用草稿与核对流程；已有其他项目或尚未归属的内容、新建项目资料、待核对提案时，提供继续现有草稿，不静默覆盖。
- 来源面板只读，Escape/关闭返回触发按钮；列表加载状态、失败重试与未加载完整的提示独立呈现。
- 仓库提供只读身份标识，包含恢复代次和工作区业务版本。修改或等版本恢复备份使旧列表及来源请求失效。

## 决策记录（ADR）

- 保留当前窗口和组件风格，不增加平行工作台、模型调用、依赖或持久化字段。
- 近期变化按已有收尾关联展示，可查看纠正与撤销后的历史回执；没有收尾关联的直接状态操作仍由既有全局变更记录承载，不伪造收尾或迁移旧事件索引。
- 当前资料无法验证历史来源时，保留当前业务值并明确说明，不将最近一条沟通当作所有字段依据。
- 项目级下一步单独显示，不伪造成独立行动；行动原日期与我方提醒分开，分别查询实际显示字段的依据。
- 在现有工作区的 `codex/project-continuity` 分支实施，保留未提交的文档归档；没有创建第二份工作区以免遗漏这些前置改动。
