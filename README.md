# Looma（灵犀胶囊）

面向独立接单者、顾问和小工作室主理人的本地优先客户跟进伴侣。

让刚结束的客户沟通有清楚的收尾，让下一次回来处理有可靠的起点：

**文字或粘贴沟通记录 → 本地草稿 → 四类核对 → 确认收尾 → 项目接续与提醒 → 独立审核的沟通纪要。**

本仓库正在建设真实案例试用版。当前 v5 围绕“记清、被打断能继续、跨日能接上、发现错误能改对”改善工作旅程，保留 v4 的原创小精灵、生活功能和长期记忆。设计与验证边界见 [v5设计](docs/specs/2026-10-27-looma-closure-v5.md)及[v5实施记录](docs/implementation-v5-status.md)；商业成效仍待真实试用。

5.1试用准备增加“放心练习一次”：演练只在当前窗口的内存里运行，关闭即丢弃，真实草稿和项目不受影响；反馈面板显示固定构建编号，仅由用户核对后主动复制/下载问题记录，不自动采集客户正文。模型配置是可选项，基础流程可直接开始。当前改进、实际验收和便携包的分发限制见 [5.1实施记录](docs/implementation-v5.1-status.md)；首次观察可使用 [15分钟任务卡](docs/试用前任务卡.md)。

## 首轮产品约定

| 能力 | 约定与边界 |
| --- | --- |
| 文字整理 | 支持文字输入和手动粘贴沟通记录；本地规则只覆盖有限句式，不承诺任意表达都能理解 |
| 草稿与中断 | 停止输入500毫秒后尝试本地保存，显示实际保存状态；查看记忆、切换空间和重开可继续最近成功保存的草稿 |
| 沟通收尾 | 按“核对内容、我方下一步、等待客户、仍待确认”组织预览；确认后生成持久回执，用户核对记录不等于客户确认共识 |
| 可信更新 | 自然语言与模型提取先核对；明确完成或重新打开事项直接保存，可撤销对应最近变更；写入结果未知时保留草稿核查 |
| 持续跟进 | 首页接续未完草稿、今日与逾期行动、最近沟通；等待客户及未定问题独立呈现，未知预算保持未知 |
| 双态分区 | 保留生活态与工作态；每种模式只处理当前空间，不自动跨区写入或扣减生活精力 |
| 模型增强 | Windows 桌面可由用户主动启用自配 OpenAI 兼容模型或 Ollama；Web 预览运行本地流程 |
| 外发纪要 | 默认生成“沟通纪要草稿／待对方确认”，用户选择字段、编辑和预览后复制文本或导出 PNG |
| 提醒 | 应用运行（含胶囊）时提醒到期事项，重开汇总遗漏；客户预计日期与用户自设回访时间分开，退出后不提醒 |
| 备份 | v5桌面完整JSONL、浏览器JSON覆盖双空间业务、草稿、跟进项、收尾与变更记录；接受既有完整备份，校验后原子替换，不含 API Key |
| 长期记忆 | 原始历史本地归档，按需检索；事实经明确确认，支持来源、纠正、置顶与主动忘记 |
| 伴侣形象 | 原创暖白浅绿小精灵，状态跟随真实操作；同一窗口可收起为220×96胶囊 |

生活态的记账、状态记录、亲友备忘与手账继续保留，首轮主要处理隔离、迁移和恢复兼容问题。用户自报的身体状态只是个人记录，不是客观生理测量或诊断。

本轮不提供语音转写、截图识别、任意结构造卡、官方模型云服务、云同步、账户支付、团队权限或多人 CRM。

## 本地运行

需要 Node.js 与 npm；优先使用可满足锁文件依赖要求的 Node.js 20 或 24。首次安装使用锁文件：

```powershell
npm ci
```

同时启动 Vite 和 Electron：

```powershell
npm run dev
```

只启动浏览器预览，打开终端输出的本地地址（默认 `http://localhost:5173`）：

```powershell
npm run dev:vite
```

构建后从本地文件启动桌面程序，不需要 Vite 服务：

```powershell
npm run build
npm start
```

`启动伴侣.bat` 提供 Windows 启动入口：缺少依赖时先执行 `npm ci`，每次重新构建，只有构建成功后才启动，避免打开旧资源。`npm run build` 生成前端资源，不等于生成已签名的安装包。

本轮还提供无需目标机器 Node/npm 的 Windows 独立启动目录生成命令：

```powershell
npm run package:trial
```

输出在 `output/trial/Looma-<构建号>-win32-x64/`。保留整个目录并运行 `Looma.exe`，不要单独复制 exe；构建号包含当前源码、锁文件和实际运行依赖字节的指纹，不只依赖 Git 提交。构建前仅清理项目内经过路径校验的 `dist`，按本次 Vite 入口的依赖清单收取资源，拒绝孤立旧资源。包只含 Electron 运行时、生产页面、主进程代码和 SQLite 必需依赖，不会复制用户数据库、模型凭据、备份或 QA 资料；已有同名构建不覆盖。源码、生产资源或运行依赖在构建后改变时，打包会拒绝继续，需重新构建。SHA256 清单用于核对本地构建内容，不能替代数字签名或证明来源可信。

便携包使用独立应用名称，默认资料目录可能与源码启动版不同；旧资料保留在原位置，需要迁移时通过原版完整备份及本版审阅导入，不会自动搬移或合并。

该产物属于**内部本地验证包**：尚未签名，既有依赖安全发布门槛和独立干净 Windows 机器的分发验收仍未完成，不能将生成目录等同于可安全公开分发。包内 `试用前请读.txt` 和 `release-status.json` 保留这一边界。正式外部真实资料试用前，负责人仍须完成对应安全升级和回归。

运行自动化检查：

```powershell
npm test
node scripts/test-native.cjs
npm run build
```

单元检查使用 Node 内置测试能力及仓库已有 TypeScript。SQLite原生检查通过Electron运行，避免误用宿主Node的ABI。安装后的脚本会检查/准备对应Electron原生二进制；网络无法下载时可用 `npm run prepare:sqlite` 重试，不静默退回旧快照。集成脚本和实际执行结果见对应版本实施记录，通过 `LOOMA_PLAYWRIGHT_MODULE` 使用外部Playwright；旧v4脚本保留其历史场景，不能替代v5验收。浏览器脚本需本地服务（默认 `http://127.0.0.1:5173`），桌面脚本需先构建；测试使用独立临时资料。受控服务仅验证管线，不证明真实云模型准确率，通知API成功也不代表用户已看到系统横幅。

## 数据与模型使用

- 桌面业务数据保存在Electron用户资料目录的`looma.sqlite`；浏览器使用IndexedDB `looma-local-v4`。生活与工作采用逻辑分区，数据库本身未加密。正常启动每类加载最近50条，历史通过游标分页查询，不再每次整体序列化档案。
- 浏览器数据库名称为兼容保留，不代表应用仍是v4；v5升级既有库结构与索引，不新建一个空库取代旧资料。工作首页各组先显示最多3项，不通过前端加载整库后筛选。
- 草稿保存不更新业务版本。确认收尾将业务变化、变更事件、收尾记录与结束草稿放在同一事务；重复确认返回同一回执。已保存但刷新失败与提交结果未知分开提示，后者保留草稿并按批次核查，避免盲目重写。
- Windows 模型凭据由 Electron 主进程使用系统提供的安全存储能力保存，模型请求也由主进程发送；安全存储不可用时不得明文落盘。Web 预览不保存或调用模型凭据。
- 旧凭据存在时，桌面每次启动均尝试安全迁移和清理；已有新连接或 Ollama 配置不会被旧配置覆盖，旧连接另作系统加密归档。仅在加密文件保存成功后清除旧浏览器字段，失败会保留并在下次启动重试；清除模型配置同时清除当前连接与旧连接归档。
- 用户启用增强后，当前输入及所选项目必要字段可能发送至其配置的模型服务。默认不附加内部备注、其他项目或另一空间资料。
- 模型回忆需要另行开启`memoryModelEnabled`，默认关闭；用户在记忆中心主动请求时，仅发送当前问题及当前空间检索出的有限证据。先展示来源，本地原文可能包含用户主动输入的私人信息，请先审阅。
- 原文保留到用户主动删除；确认事实与可重建摘要分开，摘要不自动变成事实。纠正保留被替代版本；忘记停止默认回忆并清理关联摘要。删除原文会同步清理索引、关联草稿和事件原文副本，撤销不会复活该原文，也不重新激活已结束草稿；独立确认业务字段、旧v3回退快照和已导出备份仍由用户另行处理。这是逻辑删除，不承诺磁盘取证级擦除。
- 首次迁移校验旧v3快照后写入新仓储，旧非凭据数据保留以便回退；旧版本已经截断的历史不能凭空恢复。完整备份无旧5MB硬限制；浏览器导入导出受可用内存和存储配额约束，桌面大档案采用流式JSONL与暂存数据库校验。
- 用户在当前空间主动输入的原文仍属于该空间。“未跨区写入”不表示系统已经清除原文中的全部隐私。
- 纪要只使用用户选定的信息；预算默认不选入，内部备注不进入外发草稿。导出前请核对实际文字和待办，产品不会替客户确认共识，也不会自动发送材料。
- 首次工作区为空；示例必须通过明确入口体验，不能混作真实客户记录。旧版资料在完成校验后迁移，凭据不随业务备份导出。
- 生活输入的业务更新按来源消息幂等并一次保存，原文和回复分别保存。若业务已经保存但回复失败，界面会提示查看生活卡片并不要重复提交。读取到损坏快照时保留原数据，错误页提供有效备份校验与恢复入口，不自动清空重建。

## 商业定位与验证

Looma 的首轮价值假设是减少沟通后的整理时间、减少跟进遗漏，并让记录更容易变成可审核的交付材料。价值需要真实使用证据，不能由“功能组合新颖”直接推出。

截至 2026-10-26 的一手资料核查，Dex 已有对话式联系人维护，Tana 已有语音结构化记录，folk 已有 CRM 字段自动更新。因此不使用“全球首款”或“全球没有同类产品”作为事实性宣传。[Dex 官方文档](https://getdex.com/docs/ai/voice-mode)、[Tana 官方介绍](https://outliner.tana.inc/voice-memos)、[folk 官方更新](https://www.folk.app/changelog/ai-fields)

“网站开发者同时处理多个客户”是本轮设计与工程验收的假设案例，尚无对应的真实用户研究结论。5 名目标用户、7 天试用仍待负责人安排，先核对案例，再观察责任归属、中断恢复、跨日接续及原工具补做步骤；约 50% 的整理耗时下降和重复使用目标均为实验阈值。现有 ¥28/月、¥128/席位/月只保留为后续试价参考，本轮未接入收费。没有已验证的获客成本、留存率、转化率或毛利数据。
